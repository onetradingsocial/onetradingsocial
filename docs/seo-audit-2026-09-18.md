Read-only audit of the 19-item checklist, run against both codebases and the live sites (curl, 2026-09-18). No changes made.

- **Marketing site** (repo root) is served at `https://www.tradingsocial.io`. The apex and `http://` both 308 to `https://www`, and `.html` and trailing-slash URLs 308 to the clean URL. The live `robots.txt` and `sitemap.xml` match the repo byte for byte (ignoring CRLF).
- **Product app** (`app/`, Next.js) is served at `https://app.tradingsocial.io`.

Every static page was checked by script. The app was checked by reading the source and fetching its public routes live.

## Highest-impact gaps, ranked

1. **Blog posts are client-rendered orphans.** Raw HTML for every post has the canonical `/blog-post` (which itself JS-redirects to `/blog`), post 1's title and description, an empty H1, no body, and no crawlable link from anywhere. Fix: pre-render each post to static HTML.
2. **The app has no robots.txt or sitemap.** Its catch-all `[username]` route answers `/robots.txt`, `/sitemap.xml` and `/llms.txt` with HTML at status 200. Gated pages return 200 with a meta refresh instead of a 3xx redirect, and have no noindex.
3. **Seed and internal accounts are indexable** as "verified trading track record" profiles. `generateMetadata` never checks `is_internal`.
4. **Home page image weight.** About 3.4 MB of PNG screenshots with no dimensions and no lazy loading. A 300 KB logo on every page, in 4 byte-identical copies under different names plus a fifth of the same size, so browsers cache them separately. No webp or avif.
5. **Heading structure.** Profiles have no H1, auth pages put an `h2` before the `h1`, and every static page drops from `h2` to `h5` in the footer. These are cheap, sitewide fixes.

## Evidence

### 1. sitemap.xml
- `sitemap.xml` lists 20 pages and 10 posts, and all 30 return 200 live.
- `lastmod` for home, pricing and `/for/*` says 2026-08-05, but git shows those pages changed on 2026-09-15. Terms says 2026-08-05 and changed on 2026-09-18.
- The app has no `app/src/app/sitemap.ts`, so its indexable public profiles have no sitemap. The leaderboard that would link to them is behind login.

### 2. robots.txt
- The root `robots.txt` is fine.
- The app has no `robots.ts`. Live, `app.tradingsocial.io/robots.txt` returns HTML 200 with `x-matched-path: /[username]`.

### 3. noindex
- There is no `X-Robots-Tag` in `vercel.json` or `next.config.ts`. `404.html:20` has `noindex, follow`, which is correct.
- `/blog-post` is 200 and indexable. It is the canonical target from #4, and its own script redirects to `/blog`.
- These app routes have no robots metadata and are indexable: `login`, `signup`, `forgot-password`, `check-email`, `reset-password`.
- These app routes return **200** with a 1-second meta refresh to `/login` instead of a real redirect: `leaderboard`, `feature-board`, `learn`, `messages`, `referrals`, `achievements`, `journal`, `journal/report`. The cause is `redirect()` running after streaming has started (e.g. `leaderboard/page.tsx:48-49`, `learn/page.tsx:12-15`). Middleware only 307s `/` and `/settings` (`middleware.ts:39`).
- Seed accounts from `seed-users.md` are live and indexable. For example, `/mateorivera` is titled "Mateo Rivera (@mateorivera) — verified trading track record" and has a canonical. `[username]/page.tsx:52-73` checks `is_public` and `onboarding_completed` but never `is_internal`.

### 4. Canonical
- `blog-post.html:1490,1496` hard-codes `og:url` and `canonical` to `https://www.tradingsocial.io/blog-post`. JS rewrites them per post (`:1739-1740`), but Google advises against changing the canonical with JS. The target then JS-redirects to `/blog` (`:1718-1728`).
- All other static canonicals are correct: www, no `.html`, no trailing slash.
- App:
  - Profile canonicals are correct (`https://app.tradingsocial.io/<user>`).
  - `for/[audience]/page.tsx:23` points at the www copy, which is correct.
  - `layout.tsx:31-35` has no `metadataBase`.

### 5–6. Titles and descriptions
- Static pages have no duplicate titles or descriptions.
- Titles over 60 characters: 5 compare pages, plus the hard-coded blog-post title at 82.
- Descriptions over 160 characters: index 170, pricing 184, `for/mt5` 162, and 5 compare pages at 163–178.
- `terms.html:953`: the description is only 46 characters.
- `blog-post.html:9-10`: every post's raw HTML carries post 1's title and description.
- App: the root layout (`layout.tsx:32-33`) sets the fallback title "TradingSocial" and the description "Track. Prove. Improve your trading.", which many routes inherit (check-email, reset-password, login, signup, leaderboard, …).

### 7–8. Headings
- Every static page has exactly one `h1`. `blog-post.html:1586` is `<h1 id="js-title"></h1>`, which is empty until JS runs.
- Static-page skips:
  - Footer `<h5>` on every page (e.g. `index.html:1920`).
  - FAQ `h2→h4` on pricing (`:1789`) and all 5 compare pages.
  - `index.html:1663,1704,1863` go `h2→h4`.
  - `blog.html:1631` goes `h1→h3`.
  - `blog-post.html:1619` goes `h1→h5`.
- App:
  - The profile name is a `<div className="pf-name">` (`[username]/page.tsx:351-353`), so the page has no H1.
  - `for/[audience]/page.tsx:49` goes `h1→h3`.
  - `_components/AuthShell.tsx:55` renders an `h2` before the page's `h1`.

### 9. Alt text
- Static: no img is missing alt. The empty alts (e.g. `index.html:1460`, the review avatars) are decorative, which is correct.
- App: all 27 raw `<img>` have alt. `ImageGallery.tsx` uses `alt=""` on user uploads, which is not a public SEO surface.

### 10. Schema (JSON-LD)
- All JSON-LD blocks parse.
- Home: `Organization` and `SoftwareApplication`.
- `for/*` and `compare/*`: `BreadcrumbList` and `FAQPage`.
- Blog posts: `BlogPosting` is injected by JS only (`blog-post.html:1824-1857`), with no `image`.
- Missing on pricing, `blog.html` and the legal pages.
- App: `ProfilePage` (`[username]/page.tsx:304-321`).

### 11. Internal links
- `blog.html` has 0 static `/blog/...` hrefs, and no other page links to a post. Posts are reachable only through the sitemap and JS.
- `/compare/*` is linked only from `/for/*` and `/compare/*`, not from home, pricing, the nav or the footer.

### 12. Broken links
- No broken internal hrefs or asset references.
- `/blog/<anything>` returns 200 with post 1's title (a soft 404).
- The app's unknown routes return 200 with noindex (also soft 404s).

### 13. Images
- Home page screenshots:
  - `Dashboard.png`: 1.34 MB at 1957×1221 (`index.html:1482`).
  - `Journal.png`: 1.18 MB.
  - `Leaderboard.png`: 866 KB.
  - Two more PNG screenshots at 513 KB and 307 KB.

### 14. Core Web Vitals (static signals only — no field data)
- `<script src="/consent.js">` loads synchronously in `<head>` on every page (e.g. `index.html:1288`).
- The main JS sits at the end of `<body>` without `defer`.
- 19 of 23 imgs on index lack width/height, and none are lazy-loaded. The `for/*` pages get this right (e.g. `for/forex.html:1604`).
- Each page carries 64–77 KB of duplicated inline CSS and 66 inline `@font-face` rules. They use woff2 with `font-display: swap`, but nothing is preloaded.
- App: uses `next/font`, and `next/image` appears in only 1 file.

### 15. Mobile
- Every static page and app route has a viewport meta tag.
- Static pages have 6–21 `@media` blocks each.

### 16. HTTPS
- `http://` 308s to `https://`, and `vercel.json` sets HSTS with `includeSubDomains; preload`.
- No `http://` references in either codebase.
- The apex's 308 sends only `max-age=63072000`, so it is not eligible for the preload list. Minor.

### 17. URL slugs
- `vercel.json:2-3` sets `cleanUrls: true` and `trailingSlash: false`, with the rewrite `/blog/:slug → /blog-post`.
- `/pricing.html`, `/pricing/` and `/index` all 308 to the clean URL.
- `/blog-post` and `/404` are both reachable at 200.

### 18. llms.txt
- Absent from both codebases.

### 19. Backlink strategy
- Nothing in `docs/`; the only SEO docs there are the June build plans.
- `~/marketing-plans/tradingsocial/final_plan.md:494,1210,1264` has three single-line tactics (directory listings, HARO, competitor-backlink discovery). That is not a strategy.
