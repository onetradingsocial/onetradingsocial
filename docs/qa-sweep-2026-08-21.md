# QA sweep — 2026-08-21

Exploratory browser testing of the fourteen security- and privacy-focused commits that
landed between `12c26c5` and `b68c4fd` without any browser verification. Two passes, both
run logged-out: one against the dev server, one against a production build. Plus the unit
suite, typecheck, and the Playwright e2e suite.

Published report: <https://claude.ai/code/artifact/990ba831-d5ba-4cda-90ef-c14e3452b4f5>

## Outcome

Five real defects found and fixed. One finding retracted as a test-harness artifact.
Unit tests went from 899 to 949; typecheck clean; production build succeeds.

## Fixed

### 1. The middleware had never run (High)

`middleware.ts` sat at `app/middleware.ts`. Because this project uses a `src/` directory,
Next requires it at `app/src/middleware.ts` — it raises no error, it simply never compiles
the file. `middleware-manifest.json` read `"middleware": {}` / `"sortedMiddleware": []`.

Consequences while it was dead: the auth gate never fired (pages self-gate, so nothing
leaked, but defense-in-depth was single-layered), and **`ts_ref` was never set — referral
and `utm_source` attribution had never worked at all**.

Fixed by `git mv` to `app/src/middleware.ts`. The manifest now lists it and the build
prints `ƒ Middleware`. `/` and `/settings` return real 307s; `/login` and public profile
pages stay open; no redirect loops.

> **Still untested.** The logged-in branch has *still* never executed — no pass in this
> sweep authenticated. A user whose `profiles` row is missing is treated as not-onboarded
> and parked on `/onboarding`. Every non-static request now also costs a `getUser()` call.

### 2. Declined analytics consent was ignored server-side (High)

`POST /api/track` with `ts_consent=v:1|a:0|d:0` returned `200 {"ok":true}` and wrote the
event. Consent was enforced *only* client-side in `lib/track.ts`, so any stale client,
cached bundle, in-flight beacon or direct caller bypassed the opt-out — contradicting the
promise in `CookieNotice.tsx`.

Fixed by extracting `consentFromCookie()` in `lib/consent.ts` (shared by client and server
so they cannot drift) and gating as the first statement in the route, ahead of the
rate-limit buckets. Verified against the database: declined stored 0 rows, accepted and
absent stored 1 each.

Absent and unparseable cookies remain **accepted**, deliberately — `ANALYTICS_DEFAULT` is
`true` and the product uses a documented opt-out model under Australian APP 1.4. Blocking
on absence would kill analytics for every first-time visitor.

> **Trap:** a `CONSENT_VERSION` bump re-enables analytics for people who declined, until
> they answer the notice again — version-mismatched cookies fall back to the default.

### 3. The terms checkbox did not gate the signup button (Medium)

`SignupForm.tsx` read `disabled={pending || !!problem || !pw}` — `agreed` was never
consulted, and the input had no `required`. The server rejected it, so this was a wasted
round-trip and a legal-acceptance control that looked mandatory but was not.

A comment reading *"has never gated this button"* initially looked like it blessed the
behaviour. It does not: "this button" is the **Google** button, which sits outside the
`<form>` — the comment explains why OAuth needs its own passive notice. `terms-acceptance.test.ts`
already described the checkbox as blocking the submit. The code was the outlier.

Fixed by adding `!agreed`, with an inline reason reusing the existing `.fl-err` element,
shown only once terms is the sole remaining blocker. The stale comment was corrected.

### 4. Landing pages advertised "0" traders (Medium)

`/for/*` shipped a neutral `—` placeholder server-side, then a client script overwrote it
with `(d.tradesJournaled||0)`. With an empty database that rendered a bare **0** — worse
social proof than the dash. The label also said "Traders" while the value counted *trades*,
globally, unscoped to the audience.

Fixed with a guard that only writes a finite positive number (verified against zero,
negative, missing, `null`, `NaN`, `Infinity`, non-OK responses, parse failures and rejected
fetches), and by rebinding to `activeBetaUsers`, a real trader count.

> **Accepted trade-off:** no field in `/api/stats` is audience-scoped, so the captions
> dropped their audience wording and all seven are now identical ("Traders on
> TradingSocial"). Honest over differentiated. Per-audience proof needs backend scoping.

### 5. Four public pages had no title (Low)

`/login`, `/signup`, `/forgot-password` and `/leaderboard` inherited the bare
`TradingSocial`. All four turned out to be Server Components, so a plain
`export const metadata` sufficed. `page-titles.test.ts` also asserts none of them becomes a
Client Component — Next silently ignores `export const metadata` there, which is exactly
how this would come back invisibly.

## Retracted

**`/demo` is not broken.** It was reported as permanently stuck on its loading skeleton.
The preview tab used for testing is permanently `visibilityState: "hidden"`, and Chrome
runs no `requestAnimationFrame` in hidden tabs. React 19.2 defers Suspense reveal through
rAF, so *every* streamed page appears frozen there.

Measured: rAF had not fired after 1200ms while a 50ms `setTimeout` had, and `$RT` was
`undefined`. Invoking the same reveal callback rendered the page perfectly. Pages emitting
`$RC(` stall in that harness (`/demo`, `/for/forex`, `/leaderboard`); pages that do not,
render fine. A real visitor paints in ~16ms.

Knock-on: `transformAlgorithm` is **not** implicated in any rendering fault — the HTML it
produces is byte-perfect and already carries a working reveal call. The earlier "every page
blank in dev" observation is most likely the same artifact.

> **If you test through a headless or hidden browser tab, expect this false positive.**
